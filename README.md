# Pose ON

> 사진 찍기 직전, 무슨 포즈를 할지 고민하지 않도록 도와주는 서비스

포토부스에 들어가기 전 **인원 수**와 **무드**만 고르면, 조건에 맞는 포즈를 카드로 보여준다.
카드는 좌우로 스와이프해서 넘기고, 마음에 드는 포즈는 찜해서 따로 모아볼 수 있다.

---

## 실행

이 PC에는 Node.js가 설치되어 있지 않아 **빌드 도구 없이 브라우저에서 바로 도는 구조**로 만들었다.
(ES Module을 쓰기 때문에 파일을 더블클릭하는 대신 로컬 서버로 열어야 한다.)

```
start.bat 더블클릭
```

- PC: <http://localhost:5173>
- 폰: `start.bat`이 출력하는 IPv4 주소로 접속 (예: `http://192.168.0.10:5173`) — 같은 와이파이여야 한다.
- 서버는 `Pose ON Server` 창에서 돈다. 끄려면 그 창을 닫으면 된다.

직접 실행하려면 이 폴더에서:

```bash
py -m http.server 5173
```

> `start.bat`을 수정할 때는 **줄바꿈을 반드시 CRLF로** 저장해야 한다. LF만 있으면 cmd가 명령어를 잘라 먹어서(`ipconfig` → `onfig`) 서버가 뜨기 전에 죽고 브라우저에 `ERR_CONNECTION_REFUSED`가 뜬다.

## 화면 흐름

```
#/          첫 화면        Pose ON · 카피 · [포즈 추천받기]
#/people    1단계          몇 명이 함께 찍나요?  (1명 / 2명 / 3명 이상) → [다음]
#/mood      2단계          어떤 느낌으로 찍고 싶나요? (힙한 / 밈 / ★) → [포즈 보기]
#/deck      포즈 추천      상단에 조건 표시 · 스와이프 카드 · [조건 변경] [마음에 들어요]
#/saved     찜한 포즈      저장한 포즈 격자 · 개별 찜 해제
```

조건 없이 `#/deck`으로 바로 들어오면 라우터 가드가 1단계로 되돌린다.
선택한 조건과 찜 목록은 `localStorage`에 저장되어 다시 들어와도 유지된다.

### ★ 세 번째 무드는 인원 수에 따라 이름이 바뀐다

'커플'은 두 명일 때만 성립하는 말이라, 데이터상 같은 무드(`sweet`)를 인원 수에 맞는 이름으로 보여준다.

| 인원 | 표시 이름 | 설명 |
|---|---|---|
| 1명 | **귀여운** | 사랑스럽고 러블리하게 |
| 2명 | **커플** | 다정하고 달달하게 |
| 3명 이상 | **다정한** | 서로 붙어서 친밀하게 |

무드 id(`sweet`)는 그대로라서 인원 수를 바꿔도 골라둔 무드가 풀리지 않는다.

### 카드 스와이프

**스와이프는 탐색만, 찜은 버튼만** 담당한다. 컨트롤마다 역할이 하나씩이라 실수로 저장될 일이 없다.

| 동작 | 결과 |
|---|---|
| 좌우 아무 쪽으로나 넘기기 | 다음 포즈 (저장되지 않음) |
| 짧게 끌었다 놓기 | 스프링으로 제자리 복귀 |
| `←` / `→` 키 | 넘기기 (데스크톱 확인용) |
| **[마음에 들어요] 버튼** | 찜 저장 / 해제 — 카드는 넘어가지 않는다 |

- 드래그 중 뜨는 스탬프는 양쪽 다 중립 흰색의 `다음 →` / `← 다음`이다. Action Blue는 유일한 저장 액션인 찜 버튼에만 남겨 뒀다.
- 찜하면 버튼이 `♡ 마음에 들어요` → `♥ 찜했어요`로 바뀌고 카드 좌하단에 `♥ 찜한 포즈` 배지가 즉시 붙는다. 한 번 더 누르면 해제된다.
- 뒤에 다음 카드 2장이 살짝 보이고, 카드를 넘기면 즉시 뒤에서 새 카드가 채워진다. 마지막까지 가면 처음으로 순환한다. 순환해서 다시 만난 찜한 포즈에도 배지가 그대로 붙는다.
- 되돌아오는 움직임은 CSS easing이 아니라 **손을 뗀 순간의 속도를 이어받는 스프링 시뮬레이션**(`src/lib/spring.js`)이다.

## 포즈 데이터 추가 / 교체

1. 이미지를 `pose_images/`에 넣는다. (`jpg` / `jpeg` / `png` / `webp`)
2. `src/data/poses.js`의 `POSES` 배열에 한 줄 추가한다.

```js
{
  id: 'pose39',            // 중복 불가. 찜 저장 키라서 한번 정하면 바꾸지 않는다
  file: 'pose39.jpg',      // pose_images 안의 파일명
  people: 2,               // 1 | 2 | 3   (3 = "3명 이상")
  moods: ['hip', 'sweet'], // 'hip' | 'meme' | 'sweet' — 여러 개 붙일 수 있다
  title: '백 투 백',        // 카드에 크게 보이는 이름
  tip: '등을 겹치고 고개만 카메라로 돌리기', // 실제로 어떻게 찍는지 한 줄
}
```

- 이미지 폴더 이름을 바꾸려면 같은 파일의 `IMAGE_DIR` 상수만 고치면 된다.
- 파일명은 그대로 둬도 된다. 공백·괄호가 들어간 이름(`images (1).jpeg`)도 `poseImageSrc()`가 URL 인코딩해서 처리한다.
- 이미지가 깨지거나 없으면 카드가 무너지지 않고 "이미지를 불러오지 못했어요" 상태로 표시된다.
- 어떤 조합에 포즈가 하나도 없으면 `filterPoses()`가 조건을 단계적으로 풀어(같은 인원 → 같은 무드 → 전체) 빈 화면을 만들지 않고, 화면 상단에 안내 문구를 띄운다.

### 현재 라벨 분포

`pose_images/`의 이미지를 직접 확인해 라벨링했다. `pose32`(=`pose13`), `pose36`(=`pose2`)은 해시가 같은 중복이라 제외해 **56장 중 54장**을 쓴다.

| | `hip` 힙한 | `meme` 밈 | `sweet` (귀여운/커플/다정한) |
|---|---|---|---|
| **1명** | 12 | 5 | 3 |
| **2명** | 3 | 7 | 6 |
| **3명 이상** | 12 | 13 | 10 |

한 포즈에 무드를 여러 개 붙일 수 있게 설계한 이유가 이 표다. 무드를 하나만 허용하면 `1명 + sweet`, `3명 이상 + sweet` 칸이 0장이 되어 추천이 비어버린다.

## 디자인 — DESIGN_apple.md 적용

- **단일 액센트**: 모든 인터랙티브 요소는 Action Blue `#0066cc` 하나. 어두운 화면에서는 Sky Link Blue `#2997ff`로만 바꾼다. 두 번째 브랜드 컬러는 없다.
- **밝은 타일 ↔ 어두운 타일 교차**를 화면 단위로 적용: 첫 화면(`#272729`) → 설정(파치먼트 `#f5f5f7`) → 덱(`#252527`) → 찜(흰색). 색이 바뀌는 것 자체가 구분선이다.
- **그림자는 딱 하나**: `3px 5px 30px rgba(0,0,0,.22)`를 포즈 사진 카드에만 쓴다. 버튼·카드·텍스트에는 그림자가 없다.
- **버튼 문법 2종**: pill CTA(`radius: 9999px`)와 Pearl 캡슐(`radius: 11px`). 누를 때는 시스템 공통 `transform: scale(0.95)`.
- **본문 17px / 400 / 1.47**, 디스플레이는 600 + 네거티브 자간. 중간 굵기 500은 쓰지 않는다.
- **frosted sub-nav**: 상단 바는 파치먼트 80% + `backdrop-filter: saturate(180%) blur(20px)`.
- **장식용 그라디언트 없음**: 카드 배경의 분위기는 CSS가 아니라 같은 사진을 블러 처리해 깐 것이다. 사진 비율이 제각각이라 뒤에 blur cover, 위에 원본 contain으로 얹는다.
- **폰트**: SF Pro는 애플 전용이라 `system-ui, -apple-system`으로 시작하는 스택을 쓴다. iOS/macOS에서는 실제 SF Pro로 잡히고 그 외에는 시스템 산세리프로 폴백한다. 웹폰트 요청은 0회라 오프라인에서도 그대로 뜬다.
- **터치 타깃 최소 44px**, `env(safe-area-inset-*)`로 노치·홈 인디케이터 대응.

## 확인한 것

실제 브라우저(Edge)에서 다음을 확인했다.

- 9개 조합(인원 3 × 무드 3) 모두 정확히 매칭되는 포즈가 존재
- 등록된 54장 전부 실제로 로드됨 (공백 포함 파일명 `images (1).jpeg` 포함)
- 인원 수별 세 번째 무드 이름: 1명 "귀여운" / 2명 "커플" / 3명 이상 "다정한" (무드 화면·덱 조건 칩 모두)
- 예전 버전이 저장해 둔 값(`mood:'couple'`, 삭제된 포즈 id)이 남아 있어도 앱이 깨지지 않고 정리됨
- 카드 넘김 → 카운터 순환(`1/3 → 2/3 → 3/3 → 1/3`), 덱은 항상 3장 유지
- 좌우 스와이프 모두 다음 포즈로만 넘어가고 찜 개수는 변하지 않음
- 찜 버튼은 카운터를 그대로 둔 채 저장/해제만 토글하고, 배지·버튼 라벨·상단 찜 개수가 함께 갱신됨
- 짧게 끌었다 놓으면 스프링이 `translate3d(0,0,0) scale(1)`로 정확히 복귀
- 찜 화면 저장/해제, 설정 화면 선택 상태와 CTA 활성화
- 320×568(아이폰 SE급) ~ 430×932 구간 레이아웃, 가로 오버플로 없음
- 콘솔 에러 / 미처리 예외 없음

## 알려진 제약 · 다음 단계

- **Node.js 미설치 환경**이라 React/TypeScript 빌드 파이프라인 대신 순수 ES Module로 만들었다. 타입은 JSDoc으로 달아두었으니 나중에 Node를 설치하면 `data/`, `lib/`, `components/` 구조를 그대로 유지한 채 React + TS로 옮길 수 있다.
- 포즈 라벨은 이미지를 직접 보고 붙인 것이라 주관이 들어간다. `src/data/poses.js`에서 자유롭게 수정하면 된다.
- 이미지 원본 크기가 큰 편(최대 460KB)이다. 사용 장수가 늘면 리사이즈/WebP 변환을 한 번 돌리는 게 좋다.
