# Pose ON

> 사진 찍기 직전, 무슨 포즈를 할지 고민하지 않도록 도와주는 서비스

포토부스에 들어가기 전 **인원 수**와 **무드**만 고르면, 조건에 맞는 포즈를 카드로 보여준다.
카드는 좌우로 스와이프해서 넘기고, 마음에 드는 포즈는 찜해서 따로 모아볼 수 있다.

---

## 실행

이 PC에는 Node.js가 설치되어 있지 않아 **빌드 도구 없이 브라우저에서 바로 도는 구조**로 만들었다.
(ES Module을 쓰기 때문에 파일을 더블클릭하는 대신 로컬 서버로 열어야 한다.)

```
start.bat 더블클릭
```

- PC: <http://localhost:5173>
- 폰: `start.bat`이 출력하는 IPv4 주소로 접속 (예: `http://192.168.0.10:5173`) — 같은 와이파이여야 한다.
- 서버는 `Pose ON Server` 창에서 돈다. 끄려면 그 창을 닫으면 된다.

직접 실행하려면 이 폴더에서:

```bash
py -m http.server 5173
```

> `start.bat`을 수정할 때는 **줄바꿈을 반드시 CRLF로** 저장해야 한다. LF만 있으면 cmd가 명령어를 잘라 먹어서(`ipconfig` → `onfig`) 서버가 뜨기 전에 죽고 브라우저에 `ERR_CONNECTION_REFUSED`가 뜬다.

## 화면 흐름

```
#/          첫 화면        Pose ON · 카피 · [포즈 추천받기]
#/people    1단계          몇 명이 함께 찍나요?  (1명 / 2명 / 3명 이상) → [다음]
#/mood      2단계          어떤 느낌으로 찍고 싶나요? (힙한 / 밈 / ★) → [포즈 보기]
#/deck      포즈 추천      상단에 조건 표시 · 스와이프 카드 · [조건 변경] [마음에 들어요]
#/saved     찜한 포즈      저장한 포즈 격자 · 개별 찜 해제
```

조건 없이 `#/deck`으로 바로 들어오면 라우터 가드가 1단계로 되돌린다.

### 방문마다 초기화된다

선택한 조건과 찜 목록은 **`sessionStorage`**에 담긴다. 포토부스 앞에서 여러 사람이 번갈아 쓰는 상황을 생각하면, 앞사람의 찜 목록과 인원 수가 다음 사람에게 남아 있으면 안 된다.

| 상황 | 조건·찜 목록 |
|---|---|
| 화면 이동 (홈 → 인원 → 무드 → 덱) | **유지** |
| 새로고침 (같은 탭) | **유지** |
| 탭이나 브라우저를 닫았다가 다시 접속 | **초기화** |

방문 id와 피드백 응답 여부도 같은 기준(`sessionStorage`)이다([lib/analytics.js](src/lib/analytics.js)). 조건·찜·기록·팝업이 전부 "한 방문"이라는 하나의 기준을 공유해서 서로 어긋나지 않는다. `localStorage`에는 아무것도 남기지 않는다.

### ★ 세 번째 무드는 인원 수에 따라 이름이 바뀐다

'커플'은 두 명일 때만 성립하는 말이라, 데이터상 같은 무드(`sweet`)를 인원 수에 맞는 이름으로 보여준다.

| 인원 | 표시 이름 | 설명 |
|---|---|---|
| 1명 | **귀여운** | 사랑스럽고 러블리하게 |
| 2명 | **커플** | 다정하고 달달하게 |
| 3명 이상 | **다정한** | 서로 붙어서 친밀하게 |

무드 id(`sweet`)는 그대로라서 인원 수를 바꿔도 골라둔 무드가 풀리지 않는다.

### 카드 스와이프

**스와이프는 탐색만, 찜은 버튼만** 담당한다. 컨트롤마다 역할이 하나씩이라 실수로 저장될 일이 없다.

| 동작 | 결과 |
|---|---|
| 좌우 아무 쪽으로나 넘기기 | 다음 포즈 (저장되지 않음) |
| 짧게 끌었다 놓기 | 스프링으로 제자리 복귀 |
| `←` / `→` 키 | 넘기기 (데스크톱 확인용) |
| **[마음에 들어요] 버튼** | 찜 저장 / 해제 — 카드는 넘어가지 않는다 |

- 드래그 중 뜨는 스탬프는 양쪽 다 중립 흰색의 `다음 →` / `← 다음`이다. Action Blue는 유일한 저장 액션인 찜 버튼에만 남겨 뒀다.
- 찜하면 버튼이 `♡ 마음에 들어요` → `♥ 찜했어요`로 바뀌고 카드 좌하단에 `♥ 찜한 포즈` 배지가 즉시 붙는다. 한 번 더 누르면 해제된다.
- 뒤에 다음 카드 2장이 살짝 보이고, 카드를 넘기면 즉시 뒤에서 새 카드가 채워진다. 마지막까지 가면 처음으로 순환한다. 순환해서 다시 만난 찜한 포즈에도 배지가 그대로 붙는다.
- 되돌아오는 움직임은 CSS easing이 아니라 **손을 뗀 순간의 속도를 이어받는 스프링 시뮬레이션**(`src/lib/spring.js`)이다.

## 포즈 데이터 추가 / 교체

1. 이미지를 `pose_images/`에 넣는다. (`jpg` / `jpeg` / `png` / `webp`)
2. `src/data/poses.js`의 `POSES` 배열에 한 줄 추가한다.

```js
{
  id: 'pose39',            // 중복 불가. 찜 저장 키라서 한번 정하면 바꾸지 않는다
  file: 'pose39.jpg',      // pose_images 안의 파일명
  people: 2,               // 1 | 2 | 3   (3 = "3명 이상")
  moods: ['hip', 'sweet'], // 'hip' | 'meme' | 'sweet' — 여러 개 붙일 수 있다
  title: '백 투 백',        // 카드에 크게 보이는 이름
  tip: '등을 겹치고 고개만 카메라로 돌리기', // 실제로 어떻게 찍는지 한 줄
}
```

- 이미지 폴더 이름을 바꾸려면 같은 파일의 `IMAGE_DIR` 상수만 고치면 된다.
- 파일명은 그대로 둬도 된다. 공백·괄호가 들어간 이름(`images (1).jpeg`)도 `poseImageSrc()`가 URL 인코딩해서 처리한다.
- 이미지가 깨지거나 없으면 카드가 무너지지 않고 "이미지를 불러오지 못했어요" 상태로 표시된다.
- 어떤 조합에 포즈가 하나도 없으면 `filterPoses()`가 조건을 단계적으로 풀어(같은 인원 → 같은 무드 → 전체) 빈 화면을 만들지 않고, 화면 상단에 안내 문구를 띄운다.

### 현재 라벨 분포

`pose_images/`의 이미지를 직접 확인해 라벨링했다. `pose32`(=`pose13`), `pose36`(=`pose2`)은 해시가 같은 중복이라 제외해 **56장 중 54장**을 쓴다.

| | `hip` 힙한 | `meme` 밈 | `sweet` (귀여운/커플/다정한) |
|---|---|---|---|
| **1명** | 12 | 5 | 3 |
| **2명** | 3 | 7 | 6 |
| **3명 이상** | 12 | 13 | 10 |

한 포즈에 무드를 여러 개 붙일 수 있게 설계한 이유가 이 표다. 무드를 하나만 허용하면 `1명 + sweet`, `3명 이상 + sweet` 칸이 0장이 되어 추천이 비어버린다.

## 사용 기록 · 피드백 (Supabase)

### 무엇을 기록하나

**방문 한 번당 한 행**을 만든다. 행동할 때마다 행이 쌓이는 게 아니라 그 방문의 행을 갱신한다.

| 컬럼 | 뜻 |
|---|---|
| `visit_id` | 이번 방문을 가리키는 익명 UUID (방문 1회 = 1개) |
| `liked` | 이번 방문에 찜하기를 **한 번이라도** 눌렀는가 — `true`(O) / `false`(X) |
| `score` | 이번 방문에 남긴 피드백 점수 1~5 (안 했으면 `null`) |

```
visit_id                              liked   score
────────────────────────────────────  ─────   ─────
2a7f930c-…                            X       2
342cf45d-…                            O       -
760dc0be-…                            O       5
```

- 접속하면 이번 방문의 행이 하나 생긴다 → 행 개수 = **전체 방문 수**
- 찜을 누르면 그 행의 `liked`가 O로 바뀐다 → O인 행 개수 = **찜한 방문 수**
- 찜을 눌렀다 해제해도 그 방문은 O로 남는다. 기준이 "한 번이라도 눌렀는가"이기 때문이다.
- 찜을 몇 번 누르든 요청은 방문당 한 번만 나간다.

**"방문"의 기준은 조건·찜 목록·피드백 팝업과 같다.**

| 상황 | 행이 늘어나나 |
|---|---|
| 화면 이동 · 새로고침 | 안 늘어남 (같은 방문) |
| 탭·브라우저를 닫았다 재접속 | **하나 더 생김** (새 방문) |

남는 건 무작위 UUID 하나뿐이다. 이름·이메일·IP 등 개인정보는 수집하지 않고, 사람을 방문 간에 추적하지도 않는다. 어떤 포즈를 봤는지, 몇 장 봤는지도 저장하지 않는다.

> 테스트할 때 탭을 여닫기 번거로우면 콘솔에서 `poseOnNewVisit()` 을 실행한다. 새 방문 id가 발급되어 **행이 하나 더 생긴다** (기존 행은 그대로 남는다).

테이블에 직접 쓰지 않고 `record_visit` 함수(RPC)를 호출한다. 그래야 테이블 자체를 RLS로 완전히 잠가둘 수 있다.

### 피드백 팝업

- 질문: **"오늘 실제 촬영에 도움이 되었나요?"** — 1~5점 한 번 탭으로 끝.
- **포즈 카드를 3장 이상 본 방문자에게만** 뜬다. 들어오자마자 물으면 "실제 촬영에 도움이 되었나"에 답할 근거가 없기 때문이다. 기준값은 `feedbackPopup.js`의 `MIN_VIEWED_POSES_BEFORE_ASKING`.
- **방문마다 한 번씩** 묻는다. 응답 여부를 `sessionStorage`에 담기 때문이다.

  | 상황 | 다시 묻나 |
  |---|---|
  | 같은 방문 중 화면 이동 · 새로고침 | 안 물음 |
  | 탭·브라우저를 닫았다 다시 접속 | **다시 물음** |

  질문이 "**오늘** 촬영에 도움이 되었나요"이므로 촬영할 때마다 물어야 맞다. `localStorage`에 넣으면 평생 한 번만 묻게 되어 질문과 앞뒤가 안 맞는다.
- 팝업이 열리면 그 높이만큼(`--feedback-height`) 화면 아래를 비워서 **마음에 들어요 버튼을 가리지 않는다.**

### 설정

**1. Supabase 프로젝트 생성** — [supabase.com](https://supabase.com)

**2. 테이블 만들기** — 대시보드 → **SQL Editor** → [supabase/schema.sql](supabase/schema.sql) 전체 붙여넣고 Run.
맨 아래 확인 쿼리가 `테이블_생성됨 = 1`, `정책_개수 = 1` 을 돌려주면 성공이다.

**3. 값 두 개 복사** — 대시보드 → **Project Settings → API**

| 화면에 적힌 이름 | 형태 |
|---|---|
| **Project URL** | `https://abcdefghijk.supabase.co` |
| **Project API keys → `anon` `public`** | `eyJ...` 로 시작하는 긴 문자열 (또는 `sb_publishable_...`) |

> ⚠️ 브라우저 주소창의 대시보드 URL(`https://supabase.com/dashboard/project/...`)이 아니다.
> 그걸 넣으면 요청이 엉뚱한 서버로 가서 **404**가 난다. 반드시 `.supabase.co` 로 끝나는 값이어야 한다.

**4. Vercel에 등록** — 프로젝트 → **Settings → Environment Variables**

| Key | Value | Environments |
|---|---|---|
| `SUPABASE_URL` | 3번의 Project URL | Production · Preview · Development 전부 체크 |
| `SUPABASE_ANON_KEY` | 3번의 anon 키 | 위와 동일 |

**5. 재배포** — 환경변수는 **등록 이후의 빌드부터** 반영된다. 이미 배포된 것에는 적용되지 않는다.
Deployments 탭 → 최신 배포 → ⋯ → **Redeploy**.

**6. 빌드 로그 확인** — 배포 로그에 아래가 찍혀야 한다.

```
[build-config] ✓ URL  ← SUPABASE_URL = https://abcdefghijk.supabase.co
[build-config] ✓ KEY  ← SUPABASE_ANON_KEY (208자)
[build-config] src/config.js 생성 완료
```

`⚠ Supabase 환경변수를 찾지 못했습니다` 가 찍혔다면 4번이 안 된 것이고,
`⚠ URL 형태가 이상합니다` 가 찍혔다면 3번에서 잘못된 값을 복사한 것이다.

**7. 결과 확인** — 브라우저에서 `https://<배포도메인>/src/config.js` 를 연다.
값이 채워져 있으면 성공. 빈 문자열이면 4~6단계 중 하나가 안 된 것이다.

### 환경변수가 브라우저까지 가는 방법

이 프로젝트는 빌드 없는 정적 사이트라서 브라우저가 `process.env`를 볼 수 없다. Vercel 환경변수는 **빌드 시점에만** 존재하므로, 빌드할 때 값을 파일로 구워 넣는다.

```
Vercel 환경변수
      │  vercel.json  → buildCommand: node scripts/build-config.mjs
      ▼
scripts/build-config.mjs   환경변수를 읽어
      ▼
src/config.js              값이 채워진 상태로 덮어씀
      ▼
src/lib/analytics.js       import 해서 사용
```

- 저장소의 [src/config.js](src/config.js)는 **계속 빈 값으로 두는 게 정상이다.** 배포 때만 채워진다.
- 환경변수가 없으면 빈 값으로 생성되고 빌드 로그에 경고가 남는다. 앱은 기록 전송만 생략한 채 정상 동작한다.
- 로컬에서 기록까지 테스트하려면 `src/config.js`에 값을 잠깐 넣었다가 **커밋 전에 반드시 다시 비운다.**

> **anon 키를 공개 저장소에 올려도 되나?**
> 된다. anon 키는 원래 브라우저에 노출되도록 설계된 공개 키다. 데이터를 지키는 건 키가 아니라 **RLS**다. `schema.sql`은 `visits` 테이블에 RLS를 켜고 정책을 하나도 만들지 않으므로, 키를 아는 사람도 테이블을 직접 읽거나 쓰거나 지울 수 없다. 기록은 `security definer` 함수인 `record_visit`을 통해서만 들어간다. 본인은 대시보드(service_role)로 조회하면 된다. **그 SQL을 실행하지 않은 채 키만 넣으면 안 된다.**

`config.js`가 비어 있으면 전송이 전부 조용히 생략된다. 팝업을 포함한 서비스 동작은 그대로라 로컬 개발에 지장이 없다.

### 지표 조회

`visits` 테이블 하나만 세면 된다. 바로 쓸 수 있는 SQL을 [supabase/schema.sql](supabase/schema.sql) 하단에 주석으로 넣어뒀다.

```sql
select
  count(*)                          as 전체_방문,
  count(*) filter (where liked)     as 찜한_방문,
  count(*) filter (where not liked) as 안누른_방문
from public.visits;
```

피드백 점수 분포·평균, O/X 목록, 날짜별 방문 수 쿼리도 같은 파일에 있다.

### 피드백 팝업이 안 뜰 때

**먼저 이 주소로 접속해본다.** 조건과 응답 기록을 전부 무시하고 즉시 띄운다.

```
https://<배포도메인>/?feedback=force
```

- **뜬다** → 렌더링은 정상. 아래 표에서 조건 문제를 찾으면 된다.
- **안 뜬다** → 배포가 반영되지 않았거나 CSS 문제. 브라우저를 강력 새로고침(`Ctrl+Shift+R`)하고 다시 시도한다.

콘솔에서 `poseOnDiagnose()` 를 실행하면 `팝업_노출조건` 항목이 이유를 알려준다.

| 이유 | 해결 |
|---|---|
| `아직 N장 — 포즈를 3장 봐야 뜹니다` | 덱에서 카드를 2번 더 넘긴다 (덱 진입 1장 + 2번 스와이프 = 3장) |
| `✗ 이번 방문에 이미 응답함 / 닫음` | **한 방문에 한 번만 뜨는 게 정상이다.** 탭을 닫았다 열면 다시 뜬다. 바로 보려면 `poseOnResetFeedback()` 실행 후 새로고침 |

### 데이터가 안 쌓일 때

배포한 사이트에서 **F12 → Console** 을 열고 아래를 실행한다.

```js
poseOnDiagnose()
```

설정값과 테스트 전송 결과(HTTP 상태 + 응답 본문)를 그대로 찍어준다. 결과별 원인:

| 콘솔에 나오는 것 | 원인 | 해결 |
|---|---|---|
| `설정됨: false`, `SUPABASE_URL: (비어 있음)` | 빌드에 환경변수가 안 들어감 | Vercel 환경변수 등록 → **다시 배포**. 환경변수는 등록 이후 빌드부터 반영된다 |
| `401` / `403` | RLS 정책이 INSERT 를 막음 | `supabase/schema.sql` 을 SQL Editor 에서 실행했는지 확인 |
| `404` | 테이블이 없거나 주소가 틀림 | 같은 SQL 실행 확인. `보정된_엔드포인트` 값이 `https://…supabase.co/rest/v1/events` 인지 확인 |
| `요청이 아예 나가지 못했습니다` | 네트워크 / 광고차단기 / CORS | 확장 프로그램 끄고 재시도, Supabase 프로젝트가 일시정지 상태인지 확인 |
| `성공: true` 인데 대시보드에 없음 | 다른 프로젝트를 보고 있음 | `보정된_엔드포인트` 의 도메인과 대시보드 프로젝트가 같은지 확인 |

배포된 사이트에서 `https://<도메인>/src/config.js` 를 직접 열어보면 값이 주입됐는지 바로 알 수 있다. 빈 문자열이면 빌드 단계 문제다. 이때 Vercel 빌드 로그에 `[build-config] Supabase 설정 주입 완료` 가 찍혔는지 함께 확인한다.

> **빌드 주입이 계속 말썽이면** `src/config.js` 에 값을 직접 적고 커밋해도 된다. anon 키는 원래 공개되는 키라서 RLS 만 제대로 걸려 있으면 보안상 차이가 없다. 환경변수 방식은 키를 저장소에서 분리해 두는 편의일 뿐이다.

### 한계

- 기록 전송은 fire-and-forget이다. 실패해도 재시도하지 않는다(서비스 동작이 먼저다).
- RLS로 읽기는 막혀 있지만 **쓰기 남용(스팸 INSERT)은 막지 못한다.** 공개 배포 후 문제가 되면 Supabase Edge Function을 앞에 두고 rate limit을 거는 방식으로 바꿔야 한다.
- 광고·추적 차단기가 있으면 기록이 누락될 수 있다. 절대값보다 추세로 볼 것.

## Google Analytics

[index.html](index.html) 상단에 gtag.js 태그가 들어 있다. 측정 ID는 `G-TK2CH1162M`.

Supabase 기록과 역할이 다르다. GA는 **얼마나 들어왔는지**(유입·기기·지역), Supabase는 **들어와서 뭘 했는지**(찜 여부·피드백 점수)를 본다.

알아둘 점 두 가지.

- **해시 라우팅이라 화면 이동이 기본 집계에 안 잡힐 수 있다.** 이 앱은 `#/people` → `#/mood` 처럼 해시만 바뀌므로 GA4가 페이지뷰를 접속 1회만 셀 수 있다. 화면별 이탈을 보려면 라우터에서 `gtag('event', 'page_view', ...)` 를 직접 쏘도록 추가해야 한다.
- **로컬 개발 접속도 집계된다.** `localhost`나 `192.168.x.x` 로 테스트한 것까지 실제 방문으로 잡힌다. GA 관리 → 데이터 스트림 → 내부 트래픽 정의에서 IP를 제외하거나, 보고서에서 호스트 이름으로 걸러내면 된다.

## 디자인 — DESIGN_apple.md 적용

- **단일 액센트**: 모든 인터랙티브 요소는 Action Blue `#0066cc` 하나. 어두운 화면에서는 Sky Link Blue `#2997ff`로만 바꾼다. 두 번째 브랜드 컬러는 없다.
- **밝은 타일 ↔ 어두운 타일 교차**를 화면 단위로 적용: 첫 화면(`#272729`) → 설정(파치먼트 `#f5f5f7`) → 덱(`#252527`) → 찜(흰색). 색이 바뀌는 것 자체가 구분선이다.
- **그림자는 딱 하나**: `3px 5px 30px rgba(0,0,0,.22)`를 포즈 사진 카드에만 쓴다. 버튼·카드·텍스트에는 그림자가 없다.
- **버튼 문법 2종**: pill CTA(`radius: 9999px`)와 Pearl 캡슐(`radius: 11px`). 누를 때는 시스템 공통 `transform: scale(0.95)`.
- **본문 17px / 400 / 1.47**, 디스플레이는 600 + 네거티브 자간. 중간 굵기 500은 쓰지 않는다.
- **frosted sub-nav**: 상단 바는 파치먼트 80% + `backdrop-filter: saturate(180%) blur(20px)`.
- **장식용 그라디언트 없음**: 카드 배경의 분위기는 CSS가 아니라 같은 사진을 블러 처리해 깐 것이다. 사진 비율이 제각각이라 뒤에 blur cover, 위에 원본 contain으로 얹는다.
- **폰트**: SF Pro는 애플 전용이라 `system-ui, -apple-system`으로 시작하는 스택을 쓴다. iOS/macOS에서는 실제 SF Pro로 잡히고 그 외에는 시스템 산세리프로 폴백한다. 웹폰트 요청은 0회라 오프라인에서도 그대로 뜬다.
- **터치 타깃 최소 44px**, `env(safe-area-inset-*)`로 노치·홈 인디케이터 대응.

## 확인한 것

실제 브라우저(Edge)에서 다음을 확인했다.

- 9개 조합(인원 3 × 무드 3) 모두 정확히 매칭되는 포즈가 존재
- 등록된 54장 전부 실제로 로드됨 (공백 포함 파일명 `images (1).jpeg` 포함)
- 인원 수별 세 번째 무드 이름: 1명 "귀여운" / 2명 "커플" / 3명 이상 "다정한" (무드 화면·덱 조건 칩 모두)
- 예전 버전이 저장해 둔 값(`mood:'couple'`, 삭제된 포즈 id)이 남아 있어도 앱이 깨지지 않고 정리됨
- 카드 넘김 → 카운터 순환(`1/3 → 2/3 → 3/3 → 1/3`), 덱은 항상 3장 유지
- 좌우 스와이프 모두 다음 포즈로만 넘어가고 찜 개수는 변하지 않음
- 찜 버튼은 카운터를 그대로 둔 채 저장/해제만 토글하고, 배지·버튼 라벨·상단 찜 개수가 함께 갱신됨
- 짧게 끌었다 놓으면 스프링이 `translate3d(0,0,0) scale(1)`로 정확히 복귀
- 찜 화면 저장/해제, 설정 화면 선택 상태와 CTA 활성화
- 320×568(아이폰 SE급) ~ 430×932 구간 레이아웃, 가로 오버플로 없음
- 콘솔 에러 / 미처리 예외 없음
- 피드백 팝업: 1·2장에서는 안 뜨고 3장째에 뜸, 4점 제출 → 감사 문구 → 자동 닫힘, 재요청해도 다시 안 뜸
- 팝업이 열려도 마음에 들어요 버튼이 가려지지 않음 (버튼 bottom 605 < 팝업 top 650)
- 로컬 목 서버로 실제 전송 payload 확인 — `session_start` / `pose_view` ×3 / `feedback(score=4)` / `like` 가 올바른 헤더(`apikey`, `Bearer`, `Prefer: return=minimal`)로 `/rest/v1/events` 에 전송됨
- `config.js`가 비어 있을 때도 앱이 정상 렌더링되고 전송만 생략됨
- 빌드로 생성되는 `config.js`가 따옴표·역슬래시가 섞인 키에서도 유효한 ES 모듈로 파싱되고, 그 값이 요청 헤더에 그대로 실려 나감

## 알려진 제약 · 다음 단계

- **Node.js 미설치 환경**이라 React/TypeScript 빌드 파이프라인 대신 순수 ES Module로 만들었다. 타입은 JSDoc으로 달아두었으니 나중에 Node를 설치하면 `data/`, `lib/`, `components/` 구조를 그대로 유지한 채 React + TS로 옮길 수 있다.
- 포즈 라벨은 이미지를 직접 보고 붙인 것이라 주관이 들어간다. `src/data/poses.js`에서 자유롭게 수정하면 된다.
- 이미지 원본 크기가 큰 편(최대 460KB)이다. 사용 장수가 늘면 리사이즈/WebP 변환을 한 번 돌리는 게 좋다.
